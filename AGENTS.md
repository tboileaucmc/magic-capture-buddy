- Planning data is a single shared row `planning_state` (id 'main', jsonb data + broadcast_list) readable by any signed-in user, writable only by admin/editor roles — the team shares one planning.
- `planning_state` is in the `supabase_realtime` publication and the store subscribes to its UPDATE events (unique channel name, skipNext guard against re-saving echoes) so every connected screen reflects changes without reload.
- Google Calendar/Drive/Gmail calls run server-side through connector gateway; mission invites and the weekly PDF are sent from the connected Google account.
- Mission-sheet deletion clears Calendar reminders with sendUpdates=none, then awaits authenticated cancellation with the creation event ID and sendUpdates=all before removing the planning entry; either provider failure preserves the mission for retry.
- The weekly PDF is drawn with jsPDF from data (no DOM capture) so the same code runs in the button and the Thursday cron route.
- Weekly mail callbacks use a shared Paris-calendar scheduling helper and the existing national holiday classifier; managed UTC schedules cover both daylight-saving offsets while the helper selects only the intended sending slot.
- Cinema address suggestions use authenticated Google Places text search through the connector gateway, debounced and briefly cached in memory; selecting a suggestion fills only the address to preserve the mission title and avoid overwriting manual input.
- Write access is role-based: user_roles (admin/editor) + can_edit() gate planning_state writes in RLS and in Google server functions; accounts without a role are read-only, and only admins manage roles via admin_* RPCs.
- Drive attachments are tagged with appProperties.planningAttachment so the daily purge cron only trashes app-uploaded files older than its retention window, never other Drive files.
- Validate attachment formats in the browser-safe planning-attachments helper and normalize email MIME types by extension because browsers often leave EML/MSG types empty.
- Keep mission attachments in a shared list outside the tabs and block saving while files are being read, so reopening shows saved documents immediately and slow reads cannot lose uploads.
- Scope Cinemeccanica brand tokens to `.cmc-theme` / `.cmc-theme-light`, with authentication-specific surfaces under `.cmc-auth`; mission-sheet portals explicitly receive the current planning theme, while other portals retain independent readable surfaces.
- Mission-sheet tabs group identity, periods, video calls, and documents; field state stays in the dialog so tab navigation never discards drafts.
- Waze invitation links use the public `/waze` launcher with an address-only query, requiring no session; a user-initiated Android package intent opens the app, while a separate HTTPS fallback remains available because mail clients may suppress native schemes.
- Keep planning navigation date input in a separate draft until blur or Enter, then validate before selecting the week; this prevents partial keyboard edits from resetting the displayed date.
- Classify national French holidays and weekends in the browser-safe planning-day helper, with holiday precedence and scoped theme tokens; this keeps date rules testable and mission category colors intact.
- Keep assignment stacks content-sized with explicit minimum heights, not percentage heights or flex growth inside table cells, so Firefox and Chromium expand multi-mission rows consistently without overlap.
- Store Teams meeting links separately from generic mission links and normalize them in the browser-safe calendar export helper; every invitation format includes the same link and provisional missions mask it.
- Weekly series use an rrule namespace import with a CommonJS default fallback for browser/server compatibility. Single edits/cancellations validate series/original-start identity and atomically exclude the original date; Calendar targets the instance, ICS uses RECURRENCE-ID, and series deletion removes exceptions.
- Support managers (support_editor role) may only change missions whose technicians are all in the support team (from BRABANT onward); enforced by a planning_state trigger and assertCanEditMission.
- Week duplication copies one-off missions starting in the displayed week via the browser-safe planning-duplicate helper, filtered by selected technician IDs and mission write rights; shared mission copies retain only selected technicians, get new IDs, and send no calendar invitation until saved individually.
- Raw technician profile rows are admin-only under RLS; all profile readers use get_technician_profile(), whose server-side role check and explicit public-field allowlist preserve calls while withholding confidential data from non-admins and direct exports.
- Technician extension buttons use the browser-safe 3CX URL helper to open the web dialer in a separate tab; call confirmation stays in 3CX and ordinary phone numbers retain native telephone links.
- Administration dialogs support controlled opening from the planning menu and remain mounted outside the dropdown so closing the menu does not discard the dialog.
- The support-only user-facing role reuses support_editor to preserve existing assignments and database enforcement.
